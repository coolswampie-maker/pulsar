# Публикация ПУЛЬСАР на pulsar.jaglionrus.ru (GitHub Pages)

Эта ветка (`main`) — **статическая демо-витрина**: HTML/CSS/JS без бэкенда.
Публикуется на GitHub Pages прямо из корня ветки.

Версия с настоящим бэкендом (Django + CRM + личный кабинет компании) живёт в
ветке `backend`, инструкция по её развёртыванию на VPS — там же, в `DEPLOY.md`.

---

## Что уже сделано в репозитории

- `CNAME` содержит `pulsar.jaglionrus.ru` — GitHub Pages берёт домен отсюда;
- `.nojekyll` отключает обработку Jekyll (иначе папки с `_` игнорируются);
- Pages включены, публикация из ветки `main`, папка `/ (root)`.

## Что нужно сделать один раз

**1. DNS у регистратора домена `jaglionrus.ru`**

Добавить одну запись, ничего существующего не трогая:

| Тип | Имя (поддомен) | Значение |
|-----|----------------|----------|
| CNAME | `pulsar` | `coolswampie-maker.github.io.` |

Записи `A @` и `A www` на прежний IP остаются как есть — основной сайт
продолжает работать. Обновление DNS — от 15 минут до нескольких часов.

**2. GitHub → Settings → Pages**

- **Source**: `Deploy from a branch` → ветка `main` → папка `/ (root)`;
- **Custom domain**: `pulsar.jaglionrus.ru` (должно совпадать с файлом `CNAME`);
- когда GitHub проверит DNS — поставить галку **Enforce HTTPS**.
  Сертификат выпускается автоматически, обычно за 10–30 минут после того, как
  запись CNAME разошлась по DNS.

## Проверка

- `https://pulsar.jaglionrus.ru` открывается по HTTPS;
- в каталоге 35 позиций, фотографии грузятся;
- бронь оформляется, заявка появляется в демо-кабинете оператора (`#/admin`)
  и там же подтверждается.

---

## Где на самом деле живёт pulsar.jaglionrus.ru

**Домен обслуживается не этой веткой.** `pulsar.jaglionrus.ru` указывает
A-записью на `80.78.248.86` — VPS в reg.ru, где из ветки `backend` работают
Nginx и Django (Gunicorn), код в `/srv/pulsar`. Так и задумано: инструкция
ветки `backend`, этап 3, требует именно `A pulsar → IP вашего VPS`.

Отсюда главное: **не переводите DNS на GitHub Pages, чтобы «починить» сайт.**
Это выключит рабочую версию вместе с API, кабинетом оператора и базой заявок.
Файл `CNAME` в этой ветке — наследство прежней схемы публикации; пока домен
обслуживает VPS, Pages собираются вхолостую и на сайт не влияют никак.

**Если сайт не открывается — чинить на сервере, а не здесь.** Полный порядок
диагностики и самая частая причина (затёртый после Certbot конфиг Nginx, из-за
чего на 443 никто не слушает, а `nginx -t` при этом проходит) описаны в
`DEPLOY.md` ветки `backend`. Коротко, по SSH:

```bash
sudo ss -tlnp | grep -E ':(80|443)'            # нет строки :443 → HTTPS затёрт
sudo systemctl status nginx pulsar
sudo certbot --nginx -d pulsar.jaglionrus.ru   # возвращает 443-блок
```

## Что важно знать про эту версию

**Бэкенда нет.** Заявки сохраняются в браузере посетителя (localStorage) и
никуда не отправляются. Демо-кабинет оператора показывает их и позволяет
подтвердить — этого достаточно, чтобы продемонстрировать логику, но собрать
реальные заявки так нельзя. Для этого нужна ветка `backend` на сервере.

**Один домен на репозиторий.** Файл `CNAME` задаёт единственный адрес, поэтому
прежний `pulsar.zimermans.ru` после переключения перестанет открываться.

**Правила GitHub Pages** не предполагают коммерческую эксплуатацию (продажи,
интернет-магазин). Для демонстрационной витрины это обычный сценарий, но
принимать через неё оплату нельзя.

**Доступность GitHub в РФ** не гарантирована на длительный срок. Для показа
сейчас вариант рабочий; если нужна независимость — тот же статический сайт
разворачивается на любом хостинге простым копированием файлов, либо
используется ветка `backend` на российском VPS.

## Обновление сайта

```bash
git add -A && git commit -m "что изменилось" && git push origin main
```
Pages пересобираются автоматически, изменения появляются через 1–2 минуты.
Если правились `css/`, `js/` или `data/` — поднимите номер версии в ссылках
`?v=NN` внутри `index.html`, иначе браузеры посетителей возьмут старые файлы
из кэша.
