# Публикация ПУЛЬСАР на pulsar.jaglionrus.ru (VPS + Django + Nginx)

Эта версия — с бэкендом: фронт (сайт) + REST API + кабинет оператора (`/admin`) на
одном домене `pulsar.jaglionrus.ru`. Основной сайт на `jaglionrus.ru` при этом не
трогаем: добавляется только одна запись для поддомена.

Готовые файлы конфигурации — в папке [`deploy/`](deploy/):
`nginx-pulsar.conf`, `gunicorn.service`. Переменные окружения — `backend/.env.example`.

Ниже `<ПУТЬ>` = `/srv/pulsar` (куда клонируем репозиторий на сервере).

---

## Этап 1. Подготовка

NS-серверы домена `jaglionrus.ru` уже указывают на Рег.ру (`ns1.reg.ru`), зона
управляется там же. Менять NS не нужно — это самый безопасный вариант: основной
сайт и почта не затрагиваются вообще.

Единственное, что нужно на этом этапе, — арендовать VPS и узнать его IP-адрес.
Запись в DNS добавим позже (этап 3), когда сервер уже будет отвечать.

> Перед заказом сервера в Рег.ру потребуется пройти **идентификацию аккаунта** и
> **пополнить именно облачный счёт** — без этого кнопка заказа неактивна.

## Этап 2. Сервер (VPS)

После аренды VPS с Ubuntu и получения его IP:

```bash
# пакеты
sudo apt update && sudo apt install -y python3-venv python3-pip postgresql nginx git certbot python3-certbot-nginx

# база
sudo -u postgres psql -c "CREATE USER pulsar WITH PASSWORD 'СИЛЬНЫЙ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE pulsar OWNER pulsar;"

# код
sudo git clone https://github.com/coolswampie-maker/pulsar.git /srv/pulsar
cd /srv/pulsar && sudo git checkout backend

# окружение Django
cd /srv/pulsar/backend
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt

# настройки: заполнить .env (см. backend/.env.example)
sudo cp .env.example .env && sudo nano .env
#   SECRET_KEY=...   DEBUG=0
#   ALLOWED_HOSTS=pulsar.jaglionrus.ru
#   DATABASE_URL=postgres://pulsar:СИЛЬНЫЙ_ПАРОЛЬ@127.0.0.1:5432/pulsar

# миграции, каталог, оператор, статика
sudo .venv/bin/python manage.py migrate
sudo .venv/bin/python manage.py import_catalog      # 35 позиций из booking/data/catalog.json
sudo .venv/bin/python manage.py createsuperuser     # логин в кабинет оператора
sudo .venv/bin/python manage.py collectstatic --noinput

# права на папки, которые отдаёт/пишет сервис
sudo chown -R www-data:www-data /srv/pulsar/backend/staticfiles /srv/pulsar/backend/media
```

**Gunicorn как сервис:**
```bash
sudo cp /srv/pulsar/deploy/gunicorn.service /etc/systemd/system/pulsar.service
sudo systemctl daemon-reload && sudo systemctl enable --now pulsar
sudo systemctl status pulsar        # active (running)
```

**Nginx:**
```bash
sudo cp /srv/pulsar/deploy/nginx-pulsar.conf /etc/nginx/sites-available/pulsar
sudo ln -s /etc/nginx/sites-available/pulsar /etc/nginx/sites-enabled/pulsar
sudo nginx -t && sudo systemctl reload nginx
```

## Этап 3. DNS (Reg.ру) — только когда сервер готов

Зона `jaglionrus.ru` управляется в Рег.ру, NS менять не нужно. Добавляется
**одна запись**, всё существующее остаётся нетронутым:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | `pulsar` | **IP вашего VPS** |

Записи `@` и `www` не трогаем — основной сайт продолжает работать как работал.
Почта (MX) и подтверждения владения (TXT) тоже не затрагиваются.

Обновление — обычно 15–60 минут. Проверить:
```bash
dig +short pulsar.jaglionrus.ru      # должен вернуть IP вашего VPS
```

## Этап 4. HTTPS

Только после того как `pulsar.jaglionrus.ru` резолвится на IP VPS (проверьте
`dig pulsar.jaglionrus.ru`):
```bash
sudo certbot --nginx -d pulsar.jaglionrus.ru
```
Certbot допишет 443-блок, редирект с 80 и автопродление.

Путь отступления: добавляется всего одна запись для поддомена, поэтому основной
сайт затронуть невозможно. Если что-то пойдёт не так с самим `pulsar` — удалите
запись `A pulsar` в зоне, и поддомен просто перестанет открываться, ничего
больше не изменится.

## Обновление сайта в будущем
```bash
cd /srv/pulsar && sudo git pull
cd backend
sudo .venv/bin/pip install -r requirements.txt          # если менялись зависимости
sudo .venv/bin/python manage.py migrate                  # если менялись модели
```

Изменения фронта (js/css/data в корне) подхватываются сразу — Nginx отдаёт файлы напрямую.

## Два кабинета: не путать

| | Кто входит | Адрес | Что делает |
|---|---|---|---|
| **Кабинет оператора** (CRM) | сотрудники ПУЛЬСАР | `/admin/` | заявки, календарь занятости, каталог, компании, планы по показателям |
| **Кабинет компании** (ЛК) | компании-резиденты | `#/login` → `#/cabinet` | профиль, свои заявки, отчётность по показателям ИНТЦ |

Это разные учётные записи. Оператор создаётся командой `createsuperuser` и **не может**
войти в кабинет компании (у него нет профиля компании). Компании регистрируются сами
на сайте — заводить их вручную не нужно.

**Что оператор делает с новой компанией:** в CRM → **Компании** открыть карточку и
поставить галочки:
- **«Подтверждена оператором»** — проверка пройдена;
- **«Резидент ИНТЦ»** — присвоен статус резидента.

Скидка 25% включается только когда стоят **обе** галочки. Пока их нет, компания
бронирует по базовым тарифам, а если она заявила статус резидента при оформлении,
в комментарии к заявке появится пометка «требуется проверка оператором» — сверьте
статус и при необходимости проставьте скидку в заявке вручную.

**Планы по показателям** ставит оператор: CRM → **Показатели** → поле «План». Факт
компания заполняет сама в своём кабинете. Строки показателей создаются автоматически
при первом заходе компании в раздел «Показатели».

**Подтверждающие документы** компании загружают в кабинете; файлы ложатся в
`backend/media/` (Nginx отдаёт их как `/media/`). Папка не в git — на сервере
позаботьтесь о её бэкапе вместе с базой.

## Подключение ИИ-подбора (YandexGPT)

На странице каталога есть блок «Опишите задачу своими словами». Он работает
**всегда**: без настроенной модели подбор идёт встроенным алгоритмом по словам
и синонимам. Модель улучшает результат, но её отсутствие сайт не ломает.

Чтобы включить YandexGPT:

1. В Yandex Cloud создайте сервисный аккаунт, выдайте ему роль
   `ai.languageModels.user` и получите **API-ключ**.
2. Скопируйте идентификатор каталога (`folder id`) из консоли.
3. Впишите в `backend/.env`:
   ```
   YANDEX_API_KEY=<ключ>
   YANDEX_FOLDER_ID=<идентификатор каталога>
   ```
4. `sudo systemctl restart pulsar`

Проверить настройку одной командой прямо на сервере:
```bash
cd /srv/pulsar/backend && sudo .venv/bin/python manage.py assist_check
```
Она покажет, что именно прочитано из `.env`, сделает реальный запрос и при
неудаче объяснит причину (401 — ключ, 403 — роль, 404 — folder id или модель,
429 — лимит). Ключ в выводе замаскирован.

Проверить снаружи, через сайт:
```bash
curl -s -X POST https://pulsar.jaglionrus.ru/api/assist/ \
  -H 'Content-Type: application/json' \
  -d '{"query":"нужно определить примеси в субстанции"}' | head -c 300
```
В ответе поле `"mode"`: `ai` — отвечает модель, `local` — встроенный подбор.
Если ожидали `ai`, а видите `local` — смотрите `journalctl -u pulsar -f`,
там будет строка «YandexGPT недоступен» с причиной.

**Почему это устроено просто.** Весь каталог (35 позиций, около 3 000 токенов)
помещается в один запрос к модели, поэтому векторная база, эмбеддинги и
RAG-конвейер не нужны. Если каталог вырастет до нескольких сотен позиций,
подход стоит пересмотреть — но не раньше.

**Защита от выдумок.** Модель возвращает только идентификаторы, а сервер
сверяет их с каталогом и выбрасывает всё, чего в базе нет. Предложить клиенту
несуществующий прибор система не может в принципе.

**Выбор модели.** Задача входо-ёмкая: каталог ~3 000 токенов на входе, ответ
около 100 на выходе. Поэтому решает цена входящих токенов. `aliceai-llm-flash`
(0,1 ₽ за 1000 входящих) на нашем профиле вдвое дешевле `yandexgpt-lite`
(0,2 ₽). Точные слаги копируйте из карточки модели в AI Studio. Смена модели —
одна строка в `.env` и перезапуск, код менять не нужно.

**Расходы.** Порядок величины: тысяча подборов — от 100 до 650 ₽ в зависимости
от модели. Стартовый грант Yandex Cloud (4 000 ₽) покрывает несколько тысяч
запросов. Частота ограничена параметром `ASSIST_RATE`. Рекомендуется завести
бюджет с оповещением в разделе Billing — чтобы после гранта расход не стал
неожиданностью.

## Частые вопросы
- **Фронт и API на одном домене** → в `index.html` ничего не меняем: `PULSAR_API_BASE='/api'`
  и `/admin/` работают через Nginx как есть.
- **Компания не видит скидку резидента** → в CRM у неё должны стоять обе галочки:
  «Резидент ИНТЦ» и «Подтверждена оператором».
- **Не грузятся загруженные документы** → проверьте права на `backend/media/`
  (`chown -R www-data:www-data`) и блок `location /media/` в Nginx.
- **Не открывается кабинет оператора по HTTPS (ошибка CSRF)** → проверьте, что в `.env`
  указан `ALLOWED_HOSTS=pulsar.jaglionrus.ru`: домен автоматически попадает в
  `CSRF_TRUSTED_ORIGINS`.
- **Каталог пуст** → не выполнен `import_catalog`.
- **Заявки не сохраняются** → смотрите `journalctl -u pulsar -f` и `sudo nginx -t`.
- **Подбор отвечает `local`, хотя ключ прописан** → проверьте роль сервисного
  аккаунта и доступность `llm.api.cloud.yandex.net` с сервера.
